# Периодические расчёты (механизм платформы)

Публичное описание — v8.1c.ru. Гл. 12 руководства 8.3.26 на ITS — **оглавление / за подпиской** (bookmark `TI000000655`). Bookmark `TI000000650` в той же базе открывает **гл. 11**, не гл. 12.

## Назначение

Механизм сложных периодических расчётов позволяет реализовывать модели расчёта заработной платы (примеры видов: оклад, алименты, штраф). Две стороны: описание видов расчёта и правил взаимного влияния; хранение промежуточных данных и результатов.

Объекты: **План видов расчета** (любое число) и **Регистр расчета** (несколько регистров под разделы учёта).

- Источник: [Сложные периодические расчеты](https://v8.1c.ru/platforma/slozhnye-periodicheskie-raschety/). Проверено публично, 2026-09-18.

Оглавление гл. 12 (8.3.26): общая информация; основные понятия; планы видов расчета (категория свойств «Расчет», предопределённые); регистры расчета (вытеснение, перерасчёты, редактирование). Тело — **не проверено / за подпиской**.

- Источник: [Глава 12. Периодические расчеты](https://its.1c.ru/db/v8326doc/bookmark/dev/TI000000655).

## План видов расчета

Список видов расчёта: код, наименование, реквизиты. Создаёт разработчик (предопределённые) или пользователь; **пользователь не удаляет** виды разработчика.

Влияние видов друг на друга:

- зависимость по **базовому периоду**;
- **вытеснение по периоду действия**.

Для вида указывают перечни: от каких зависит по базе; какие его вытесняют. **Ведущие** виды расчёта — не прямая зависимость, но влияние через другие виды.

Формы: список, вид расчёта, выбора.

- Источник: [План видов расчета](https://v8.1c.ru/platforma/plan-vidov-rascheta/).

## Регистр расчета

Записи: измерения + ресурсы. Связан с **одним** планом видов расчета → у записи поле **Вид расчета**. Обязательное поле **Период действия**; разработчик задаёт минимальную периодичность.

Как правило, изменение при проведении документа: регистратор и номер строки; добавление/изменение/удаление — только для всех записей одного документа вместе. Уникальность: не две записи одной строки одного документа.

**График времени** — регистр сведений (пример измерений: график работы и дата; ресурс — рабочие часы). Запись регистра расчета можно связать с графиком и получать часы встроенным языком.

**Перерасчеты** — объекты внутри регистра: какие записи утратили актуальность из‑за зависимости по базе и вытеснения.

- Источник: [Регистр расчета](https://v8.1c.ru/platforma/registr-rascheta/).

### Вытеснение по периоду действия

Запись содержит две даты периода действия. Если вид может быть вытеснен, это **запрашиваемый** период. Фактический период — после анализа вытесняющих записей: набор периодов, подмножество исходного; если вытеснителей нет — равен периоду действия; при полном вытеснении фактический период **отсутствует**. Какие записи вытесняют — по плану видов расчета.

### Зависимость по базовому периоду

**База** — число для расчёта результата данной записи, из результатов записей, от которых вид зависит по базе. В записи — две даты базового периода. Два вида зависимости:

- по **периоду действия** — пересечение фактического периода влияющей записи с базовым периодом; база пропорциональна перекрытию с учётом графика;
- по **периоду регистрации** — записи, у которых «Период регистрации» попадает в базовый период.

Сложный случай: свойство «Период действия является базовым периодом» — базой служит фактический период действия после вытеснения (набор периодов).

### Формирование записей перерасчета

Отслеживает появление записей, влияющих на уже существующие (по взаимному влиянию видов, вытеснению и базе). Результат — набор сведений, какие записи нужно рассчитать заново.

Возможности, перечисленные на странице: выбор записей; по регистратору; база; данные графика; данные о перерасчёте; чтение/изменение/запись набора.

- Источник: [Регистр расчета](https://v8.1c.ru/platforma/registr-rascheta/).

## Что по-прежнему закрыто

Полный API встроенного языка, сторнирование, таблицы БД, свойства метаданных гл. 12 — не выгружались. Не описывать расчёт зарплаты типовых конфигураций.
