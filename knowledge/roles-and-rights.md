# Роли и права

## Назначение

Система прав доступа описывает наборы прав, соответствующие должностям или виду деятельности. Структура прав задаётся прикладным решением. Для объектов в БД (справочники, документы, регистры и т. д.) могут быть права на отдельные поля и записи (пример: документы только определённых контрагентов).

- Источник: [Система прав доступа](https://v8.1c.ru/platforma/sistema-prav-dostupa/). Проверено публично, 2026-09-16.

**Роли** — общие объекты конфигурации для ограничения прав. Роль может соответствовать должностям или видам деятельности. Роль определяет, какие действия над какими объектами метаданных может выполнять пользователь. Каждому пользователю ставится в соответствие **одна или несколько ролей**. При запрещённом действии оно не выполняется, система показывает предупреждение.

Редакторы: **Редактор роли** (одна роль) и **Редактор «Все роли»** (несколько/все роли).

- Источник: [Роль](https://v8.1c.ru/platforma/rol/); [Объекты конфигурации 1С:Предприятия 8](https://its.1c.ru/db/content/metod8dev/src/platform81/startersdev/i8102579.htm), «Роли» (несколько ролей у пользователя — отличие от 7.7).

Оглавление руководства 8.3.26: 5.5.4 «Роли и права доступа» (привилегированный режим, безопасный режим, режимы удаления, правила сочетания ролей, редактор прав, ограничение доступа к данным, язык ограничений, шаблоны, конструктор). Тело — **не проверено / за подпиской**. Не выдумывать полный список прав объектов.

- Источник: [Глава 5. Объекты конфигурации](https://its.1c.ru/db/v8326doc/bookmark/dev/TI000000167), п. 5.5.4.

## Интерактивные и основные права

Все права делятся на **основные** и **интерактивные**.

- Основные описывают действия над элементами данных или системой в целом и **проверяются всегда**, независимо от способа обращения.
- Интерактивные — действия пользователя интерактивно; проверяются только при интерактивных операциях стандартными способами. В клиент-серверном варианте все проверки прав **кроме интерактивных** выполняются на сервере.

Связь (пример из документации): основное **Удаление** — интерактивные **Интерактивное удаление** и **Интерактивное удаление помеченных**. Если запрещено Удаление — запрещены и интерактивные удаления. Если разрешено Интерактивное удаление помеченных — Удаление тоже разрешается.

Цепочки зависимостей система отслеживает сама (снятие права снимает зависимые; установка — устанавливает те, от которых право зависит).

Зафиксированная цепочка из текста:

- Интерактивное удаление помеченных требует интерактивного **Редактирование**.
- Редактирование требует интерактивного **Просмотр**.
- Интерактивное удаление помеченных требует основного **Удаление**.
- Интерактивное Редактирование требует основного **Изменение**.
- Интерактивное Просмотр требует основного **Чтение**.
- Основные **Изменение** и **Удаление** требуют основного **Чтение**.

- Источник: [Система прав доступа](https://v8.1c.ru/platforma/sistema-prav-dostupa/), «Интерактивные и основные права».

## Ограничение на уровне записей и полей (RLS)

Для действий **чтение**, **добавление**, **изменение**, **удаление** в ролях могут быть дополнительные условия на данные. Действие выполняется, только если условие для данных объекта — «истина». Аналогично для таблиц без объектной природы (регистров).

Для объектных таблиц и регистров сведений ограничения можно задавать **на разные поля**.

Условие — на языке, **подмножестве языка запросов**, по каждой записи. Можно уточнять инструкциями препроцессора (`#ЕСЛИ`, `#ТОГДА` и др.). Списки и отчёты можно показывать только по разрешённым данным.

Для регистров накопления, бухгалтерского учёта и расчёта условия разграничивают доступ **по значениям измерений** (для бухгалтерии — по балансовым измерениям). Для объектных данных и регистров сведений — **по любым полям**.

Условия вводятся вручную или конструктором ограничений доступа к данным.

- Источник: там же, «Ограничение доступа к данным на уровне записей и полей».

## Параметры сеанса

Объекты прикладного решения для использования в ограничениях доступа текущего сеанса (и для других целей). Значения сохраняются в течение сеанса. Снижают время доступа при RLS.

- Источник: там же, «Параметры сеанса». Детали API — **не проверено / за подпиской**.

## REST и права

При чтении и записи через REST платформа выполняет обычные проверки прав и вызывает обработчики событий, **кроме проверки заполнения**.
