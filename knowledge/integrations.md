# Интеграции

## Назначение

«1С:Предприятие 8» описывается как открытая система: обмен файлами, доступ к объектам из внешних приложений, протоколы и стандарты (в тексте явно: XML, JSON и т. п.), Интернет и электронная почта. Поддерживаются создание web- и HTTP-сервисов и работа с внешними web- и HTTP-сервисами; доступ внешних систем к данным по **OData**. Возможна интеграция с оборудованием (в т.ч. торговым и складским). Распределённые ИБ; универсальный обмен с системами не на платформе «1С:Предприятие».

- Источник: [Интеграция](https://v8.1c.ru/platforma/integraciya/). Проверено публично, 2026-09-16.

Глава 15 руководства — обмен данными; гл. 16 — XML (XDTO), JSON, двоичные данные; гл. 17 — интернет-сервисы, сервисы интеграции, внешние источники данных и т. д. Тела глав — **не проверено / за подпиской**.

- Источник: [Введение](https://its.1c.ru/db/content/v8326doc/src/%D1%80%D1%83%D0%BA%D0%BE%D0%B2%D0%BE%D0%B4%D1%81%D1%82%D0%B2%D0%BE%20%D1%80%D0%B0%D0%B7%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D1%87%D0%B8%D0%BA%D0%B0/%D0%B2%D0%B2%D0%B5%D0%B4%D0%B5%D0%BD%D0%B8%D0%B5.htm), «Структура Руководства».

Оглавление гл. 5: XDTO-пакеты, Web-сервисы, HTTP-сервисы, WS-ссылки, планы обмена.

## REST / OData

После публикации прикладного решения на веб-сервере сторонние системы обращаются HTTP-запросами. Автогенерируемый REST — основной инструмент интеграции (по тексту v8.1c.ru). Позволяет читать, изменять, создавать и удалять объекты данных.

Протокол: **OData 3.0**. Ответы: Atom/XML или JSON. В платформе реализована **только серверная** часть REST; клиент к чужим REST — средствами работы с HTTP.

Публикация REST в конфигураторе на веб-сервере. Аутентификация совпадает с web-сервисами. Клиенты могут запросить документ метаданных.

**Доступны практически все основные объекты:** справочники, документы, константы, перечисления, планы обмена, регистры накопления, расчёта, бухгалтерии и сведений, виртуальные таблицы периодического регистра сведений, регистров бухгалтерии и накопления, планы счетов, видов характеристик и видов расчёта, бизнес-процессы, задачи, журналы документов.

Дополнительно названы методы: проведение и отмена проведения документа; выполнение задачи; старт бизнес-процесса; срез первых/последних регистра сведений; остатки/обороты регистров накопления и бухгалтерии; для регистра расчёта — данные графика, фактический период действия, перерасчёт и база.

Ошибки: HTTP 4XX (клиент, возможен внутренний код и сообщение) или 5XX (сервер). Проверки прав и обработчики событий выполняются, **кроме проверки заполнения**. Фильтрация списков — стандартные условия OData (в тексте пример `$filter`).

- Источник: [REST интерфейс](https://v8.1c.ru/platforma/rest-interfeys/).

## HTTP-сервисы

Собственные произвольные HTTP-сервисы в дополнение к авто-REST. Ответ формирует разработчик: доступ к телу, заголовкам и строке запроса; код, тело и заголовки ответа — по своему усмотрению.

Сравнение с SOAP web-сервисами (по тексту): проще клиент; потенциально меньше данных и нагрузки; ориентация на ресурсы, а не на действия. Важно для мобильных устройств.

Объект конфигурации **HTTP-сервис** в ветке **Общие — HTTP-сервисы**. Сервис содержит шаблоны (путь, в т.ч. параметризованные сегменты `{какой-то текст}`) и методы (конкретный HTTP-метод или любой из доступных + процедура обработчика).

Если URL не сопоставлен шаблону/методу — код **404 Not Found**. Иначе в обработчик передаётся **HTTPСервисЗапрос**; ответ — **HTTPСервисОтвет**.

Публикация, аутентификация, разделение данных и отладка — аналогично web-сервисам.

- Источник: [HTTP-сервисы](https://v8.1c.ru/platforma/http-servisy/).

## Web-сервисы (SOAP / SOA)

Средство поддержки SOA. Прикладное решение — поставщик и/или потребитель.

Объект **Web-сервис**: операции и параметры; типы через **XDTO**. Модуль с процедурами операций. Публикация на IIS или Apache через файловую систему.

Взаимодействие поставщика с потребителями — через веб-сервер (модуль расширения веб-сервера) в обоих вариантах работы ИБ. Исполнение модуля: кластер (клиент-сервер) или модуль расширения веб-сервера (файл). Как потребитель — вызывает клиентское приложение. Для потребителя поддерживается MTOM (включается автоматически).

- Источники: [Web-сервисы](https://v8.1c.ru/platforma/web-servisy/); [Web-сервис](https://v8.1c.ru/platforma/web-servis/).

## JSON

Слои работы: потоковая запись/чтение (без всего документа в памяти); сериализация примитивов и коллекций; сериализация прикладных типов через XDTO (рекомендуется прежде всего между двумя прикладными решениями 1С). Можно задать функции преобразования/восстановления. HTTP-сервисы могут возвращать JSON; можно указать использование BOM.

- Источник: [JSON](https://v8.1c.ru/platforma/json/).

## Универсальный обмен данными

Для территориально распределённых систем на 1С и обмена с **другими** ИС. Переносит **только данные**; конфигурацию и административную информацию этим механизмом перенести нельзя.

Формат обмена — XML. Между ИБ 1С **не требуется** идентичность конфигурации и структуры объектов. Несколько независимых схем обмена; топологии «звезда», «снежинка» и др.

Составные части: **План обмена** (узлы и состав данных; служба регистрации изменений; инфраструктура сообщений — у сообщения есть план, отправитель, получатель, целочисленный номер); XML-сериализация; чтение/запись XML.

- Источник: [Универсальный механизм обмена данными](https://v8.1c.ru/platforma/universalnyy-mekhanizm-obmena-dannymi/).
